신뢰할 만한 학술지에 최근 발표된 정신의학 논문 중 **매일 3편**을 골라
제목·저자·핵심 결론을 한 화면에서 보여주는 웹페이지입니다.

- 데이터: 미국 국립의학도서관 **PubMed** 공개 API (무료, 회원가입 불필요)
- 설치할 것: **없음** (파일 3개가 전부)
- 비용: **0원**

## 1단계 — 인터넷에 올려서 열어보기 (아이패드·아이폰 필수)

이 페이지는 PubMed에서 논문을 받아옵니다. 그런데 **아이패드·아이폰의 사파리는
기기에 저장된 파일이 외부 인터넷으로 요청 보내는 것을 보안상 막습니다.**
그래서 파일을 탭해서 여는 방법은 통하지 않습니다. 대신 **인터넷에 올리면 됩니다. 무료입니다.**

## 아이패드로 작업할 때 — 코드 고치는 방법

아이패드에는 메모장이나 터미널이 없지만, **브라우저만으로 코드를 고칠 수 있습니다.**

### 방법 A — GitHub 웹 편집기 (간단한 수정용)

1. 사파리에서 저장소를 열고 고칠 파일(`app.js` 등)을 탭
2. 오른쪽 위 **연필 아이콘** ✏️ 을 탭
3. 내용을 고친 뒤 아래로 내려 **Commit changes** 를 탭
4. 1~2분 뒤 배포된 주소를 새로고침하면 반영됩니다

### 방법 B — github.dev (여러 파일을 함께 볼 때)

주소창에서 `github.com` 을 **`github.dev`** 로 바꾸면 됩니다.

```
https://github.dev/logos113/Project-begins
```

VS Code라는 전문 편집기의 웹 버전이 열립니다. 왼쪽에 파일 목록이 나오고,
고친 뒤 왼쪽 갈래 아이콘에서 저장(Commit)하면 됩니다. **설치할 것은 없습니다.**

> 아이패드 화면 키보드로는 `{ }` `[ ]` 같은 기호를 치기가 번거롭습니다.
> **처음에는 저에게 "이렇게 바꿔줘" 라고 말씀하시는 편이 훨씬 빠릅니다.**
> 코드가 눈에 익은 다음에 직접 고쳐보셔도 늦지 않습니다.

### 아이패드에서 안 되는 것

- **터미널 명령** (`npm`, `node`, `python3`) — 5단계의 테스트 실행이 여기 해당합니다.
  필요할 때 저에게 말씀해 주시면 제가 대신 돌려서 결과를 알려드리겠습니다.
- 그 외에는 데스크탑과 차이가 없습니다.

## 다른 기기에서 이어서 작업하기 (아이패드 ↔ 데스크탑)

**코드는 아이패드가 아니라 GitHub에 저장되어 있습니다.** 그래서 어느 기기에서든
이어서 작업할 수 있습니다. 기기를 바꿔도 처음부터 다시 만들 필요가 전혀 없습니다.

```
              ┌──────────────────┐
              │     GitHub       │  ← 진짜 원본
              └────────┬─────────┘
         받아오기 ↓        ↑ 올리기
        ┌──────────────┴──────────────┐
     아이패드                      데스크탑
```

### 방법 1 — 아무것도 설치하지 않기 (가장 쉬움)

데스크탑에서도 브라우저로 그냥 하면 됩니다. 아이패드와 완전히 똑같습니다.

```
https://github.dev/logos113/Project-begins
```

설치할 것도, 받아올 것도 없습니다. **어느 기기에서든 항상 최신 상태**입니다.
기기를 자주 바꾸신다면 이 방법이 제일 속 편합니다.

### 방법 2 — 데스크탑에 제대로 갖추기 (권장)

> **윈도우 PC를 쓰신다면 [SETUP-WINDOWS.md](SETUP-WINDOWS.md) 에 설치부터 첫 실습까지
> 단계별로 자세히 적어두었습니다.** 아래는 요약입니다.

코드가 늘어나면 내 컴퓨터에 두고 작업하는 편이 훨씬 편합니다.
**명령어를 몰라도 됩니다.** 클릭으로 하는 프로그램이 있습니다.

**설치할 것 2개 (둘 다 무료)**

| 프로그램 | 역할 | 주소 |
|---|---|---|
| **GitHub Desktop** | GitHub에서 받아오고 올리기 | desktop.github.com |
| **VS Code** | 코드 편집기 | code.visualstudio.com |

**처음 한 번만 하는 설정**

1. GitHub Desktop 실행 → GitHub 계정으로 로그인
2. `File` → `Clone repository` → 목록에서 **Project-begins** 선택 → `Clone`
   *(Clone = 내 컴퓨터로 복사해오기)*
3. 저장할 폴더를 정하면 끝입니다. 코드가 내 컴퓨터에 생깁니다.

**작업할 때마다 하는 3단계**

```
① 시작 전   GitHub Desktop 에서  Fetch origin  →  Pull  (최신 내용 받아오기)
② 작업      VS Code 로 파일을 고치고 저장
③ 끝나면    GitHub Desktop 에 바뀐 내용이 뜸
            → 아래에 무엇을 고쳤는지 한 줄 적고  Commit  →  Push
```

### ⚠️ 가장 많이 겪는 문제 — 반드시 읽어주세요

**작업을 시작하기 전에 항상 먼저 받아오세요(Pull).**

이런 상황을 조심해야 합니다.

```
월요일  아이패드에서 색깔을 바꾸고 Commit          → GitHub에 반영됨
화요일  데스크탑에서 Pull 을 안 하고 그냥 작업       → 내 컴퓨터는 아직 월요일 이전 상태
        Push 하려고 하면 "충돌(conflict)" 이라며 거부당함
```

**규칙은 하나뿐입니다: 작업 시작 = Pull, 작업 끝 = Push.**
이것만 지키면 거의 문제가 생기지 않습니다.

혹시 충돌이 나더라도 **코드가 사라지지는 않습니다.** GitHub에는 모든 기록이 남아 있어서
언제든 되돌릴 수 있습니다. 막히시면 저에게 말씀해 주세요.

### 저(Claude)와의 대화는 어떻게 되나요?

- **코드**는 GitHub에 있으므로 100% 안전합니다.
- **대화 기록**은 같은 계정으로 `claude.ai/code` 에 접속하면 세션 목록에서 찾을 수 있습니다.
  데스크탑 앱이나 브라우저 어느 쪽이든 됩니다.
- 설령 예전 대화를 못 찾더라도 괜찮습니다. **이 README가 인수인계 문서 역할**을 합니다.
  새 대화를 열고 이 저장소를 보여주면서 "이어서 작업하고 싶다"고 말씀하시면 됩니다.

## 2단계 — 파일 3개가 하는 일

웹페이지는 보통 파일 3개로 이뤄집니다. 사람으로 비유하면 이렇습니다.

| 파일 | 역할 | 비유 |
|---|---|---|
| `index.html` | 무엇이 있는지 (제목, 버튼, 목록) | **뼈대** |
| `style.css` | 어떻게 보일지 (색, 크기, 여백) | **옷** |
| `app.js` | 무엇을 할지 (논문 가져오기, 버튼 반응) | **두뇌** |

세 파일 모두 **메모장으로 열어서 고칠 수 있는 그냥 글자 파일**입니다.
특별한 프로그램이 필요 없습니다. 한 줄 한 줄 한국어 주석을 달아두었으니
위에서부터 천천히 읽어보시면 무슨 일이 일어나는지 보입니다.

> 참고: 이 코드는 배우기 쉽도록 변수 이름을 **한글로** 지었습니다.
> 실제 개발 현장에서는 영어를 씁니다(`papers`, `loadPapers` 등).
> 익숙해지신 뒤에 영어로 바꿔보는 것도 좋은 연습입니다.

### 이 페이지가 동작하는 순서

```
페이지 열림
   ↓
[app.js] 검색 조건을 문장으로 조립
         예: (JAMA Psychiatry 또는 Lancet Psychiatry ...) 그리고 최근 30일
   ↓
[app.js] PubMed에 물어봄  →  논문 번호 60개를 받음
   ↓
[app.js] 오늘 날짜를 기준으로 그중 3개를 고름
         (그래서 하루 동안은 같은 3편, 다음 날엔 다른 3편)
   ↓
[app.js] 그 3편의 제목·저자·초록을 다시 받아옴
   ↓
[app.js] 카드 모양으로 화면에 그림  →  [style.css]가 예쁘게 꾸밈
```

## 3단계 — 직접 고쳐보기

코딩은 읽는 것보다 **고쳐보는 것**으로 빨리 늡니다.
아래는 안전하게 바꿔볼 수 있는 것들입니다.

- **아이패드**: 위의 "코드 고치는 방법"대로 고치고 **Commit** → 1~2분 뒤 배포 주소를 새로고침
- **데스크탑**: 파일을 고치고 **저장** → 브라우저 새로고침(F5)

### (1) 하루에 보여줄 편수 바꾸기 — `app.js`

```js
const 보여줄_편수 = 3;      // 이 숫자를 5로 바꾸면 5편이 나옵니다
```

### (2) 학술지 추가·제거하기 — `app.js`

`정신의학_학술지` 목록에 한 줄 추가하면 됩니다.

```js
const 정신의학_학술지 = [
  "Lancet Psychiatry",
  "JAMA Psychiatry",
  "Sleep Med",            // ← 이렇게 추가
];
```

이름은 PubMed의 **공식 약어**를 써야 합니다. 확인하는 방법:
PubMed에서 그 학술지 논문 아무거나 열면 제목 위에 약어가 나옵니다
(예: `Sleep Med. 2026 Mar;` → 약어는 `Sleep Med`).

### (3) 관심 분야 추가하기 — `index.html` + `app.js`

두 곳을 함께 고쳐야 합니다. 예로 "여성 정신건강"을 추가한다면,

`index.html` 의 분야 목록에 한 줄:
```html
<option value="women">여성 정신건강</option>
```

`app.js` 의 `분야별_키워드` 에 한 줄:
```js
women: ["perinatal", "postpartum", "premenstrual", "menopause"],
```

> `value="women"` 과 `women:` 의 **이름이 똑같아야** 연결됩니다. 여기가 자주 틀리는 부분입니다.

### (4) 색깔 바꾸기 — `style.css`

맨 위 `:root` 안의 색상 코드만 바꾸면 전체 분위기가 바뀝니다.

```css
--accent: #1c5d7a;   /* 강조색. 예: #7a1c3d 로 바꾸면 자주색 계열 */
```

색상 코드는 구글에 "color picker"를 검색하면 쉽게 고를 수 있습니다.

### (5) 저장한 논문은 어디에 보관되나 — `app.js`

논문 카드의 **☆ 저장** 버튼을 누르면 브라우저 안의 저장 공간(localStorage)에 보관됩니다.

- **이 기기, 이 브라우저에만** 저장됩니다. 서버로 전송되지 않아 다른 사람은 볼 수 없습니다.
- 아이패드에서 저장한 것은 데스크탑에서 보이지 않습니다 (기기마다 따로입니다).
- 사파리 `방문 기록 및 웹사이트 데이터 지우기` 를 하면 함께 지워집니다.
- 용량 절약을 위해 초록 전문은 저장하지 않습니다. 전문은 PubMed 링크로 보세요.

보관함 이름을 바꾸고 싶으면 `app.js` 의 이 부분을 고치면 됩니다.

```js
const 북마크_보관함_이름 = "psychiatry-digest-bookmarks";
```

> 이름을 바꾸면 **기존에 저장해둔 논문이 보이지 않게 됩니다.** (지워지는 것은 아니고,
> 다른 서랍을 열게 되는 것입니다) 특별한 이유가 없으면 그대로 두세요.

### (6) 학술지 우선순위 조정하기 — `app.js`

화면에서 **"권위 높은 학술지 우선"**을 고르면, 등급이 높은 학술지 논문이
더 자주 보입니다. 등급은 `app.js` 의 `학술지_등급` 표에 적혀 있습니다.

```js
const 학술지_등급 = {
  "JAMA": 5,                 // 5등급 — 가장 자주 보임
  "Lancet Psychiatry": 4,
  "Psychol Med": 2,
  "J Affect Disord": 1,      // 1등급 — 가끔 보임
};
```

**이 등급은 절대적인 기준이 아닙니다.** 전공하신 분의 판단이 더 정확할 수 있으니
자유롭게 고치세요. 숫자를 올리면 더 자주, 내리면 덜 보입니다.
표에 없는 학술지는 자동으로 1등급이 됩니다.

> **Impact Factor를 직접 가져오지 않는 이유**
> IF는 Clarivate 라는 회사의 유료 데이터라 무료로 가져올 수 없고,
> 수치를 그대로 옮겨 적는 것도 라이선스 문제가 있습니다.
> PubMed 역시 IF 정보를 제공하지 않습니다.
> 그래서 대략적인 위상을 등급으로 나누어 직접 적어두는 방식을 씁니다.

낮은 등급도 완전히 배제되지는 않습니다. 365일치로 확인한 결과,
5등급은 약 160회, 1등급은 약 26회 등장합니다 (매일 3편 기준).

### (7) 홈 화면 아이콘 바꾸기

아이콘 그림은 `tools/make_icons.py` 가 만들어 냅니다.
맨 위의 색깔만 바꿔도 분위기가 달라집니다.

```python
배경색   = (0x1c, 0x5d, 0x7a)   # 진한 청록  (숫자 3개 = 빨강, 초록, 파랑)
종이색   = (0xff, 0xff, 0xff)   # 흰색
```

고친 뒤 `python3 tools/make_icons.py` 를 실행하면 `icons/` 안의 그림 4개가 새로 만들어집니다.
**아이패드에서는 이 명령을 실행할 수 없으니**, 원하시는 색이나 모양을 저에게 말씀해 주세요.

## 5단계 — 고장 안 나게 지키기 (선택)

`tests/` 폴더 안의 두 파일이 **테스트**입니다.
코드를 고친 뒤 이걸 실행하면, 망가진 곳이 있는지 자동으로 알려줍니다.

```bash
npm install jsdom
node tests/logic.test.mjs       # 동작 검사
node tests/html.test.mjs        # 구조 검사
node tests/conclusion.test.mjs  # 결론 추출 검사
node tests/flow.test.mjs        # 전체 흐름 검사
```

| 파일 | 검사하는 것 |
|---|---|
| `logic.test.mjs` | 초록 파싱, 저자 표기, 검색어 조립, 학술지 다양성(30일치), 특수문자 처리 |
| `html.test.mjs` | 주석 중첩, `<head>` 구조, 아이콘 위치와 크기, 연결된 파일의 존재 여부 |
| `flow.test.mjs` | 가짜 PubMed로 검색부터 화면 그리기까지 끝까지 이어서 확인 |

`html.test.mjs` 는 실제로 겪은 문제 때문에 만들어졌습니다.
주석 안에 주석을 넣는 실수로 `<head>` 가 통째로 비어버려 아이콘이 무시됐는데,
**화면은 멀쩡해 보여서** 원인을 찾는 데 한참 걸렸습니다.
이제 같은 일이 생기면 이 검사가 즉시 잡아냅니다.

> **아이패드에서는 이 명령을 실행할 수 없습니다.** 코드를 고친 뒤 확인이 필요하시면

### 일반 도메인 연결 (`.com`, `.kr`)

GitHub Pages 는 커스텀 도메인을 정식 지원합니다. **호스팅은 계속 무료**이고
도메인 구입비만 듭니다 (.com 연 1.5~2만원, .kr 연 2~3만원).

1. 도메인 구입 (가비아·후이즈 / Cloudflare·Namecheap)
2. 구입처 DNS 설정에서 GitHub 주소를 가리키게 지정
3. 저장소에 `CNAME` 파일 추가
4. Settings → Pages → Custom domain 입력 → **Enforce HTTPS** 체크

HTTPS 인증서는 GitHub 가 무료로 발급하고, 기존 주소도 계속 함께 작동합니다.
DNS 에 넣을 IP 는 바뀔 수 있으니 설정할 때 GitHub 공식 문서에서 확인하세요.

> 개인 용도라면 굳이 없어도 됩니다. 남에게 보여주거나 여러 사람이 쓰게 될 때 의미가 있습니다.
