# Project-begins

직접 만들어 쓰는 웹앱 세 개가 들어 있는 저장소입니다.
설치할 것도, 서버도, 비용도 없습니다. 브라우저만 있으면 됩니다.

## 무엇이 들어 있나

| 앱 | 주소 | 폴더 | 설명서 |
|---|---|---|---|
| **Dr. Y's Archive** (첫 화면) | `.../Project-begins/` | `index.html` | 아래 참고 |
| **오늘의 정신의학 논문** | `.../Project-begins/psychiatry/` | `psychiatry/` | [psychiatry/README.md](psychiatry/README.md) |
| **오늘의 일본어 여행 회화** | `.../Project-begins/japanese/` | `japanese/` | [japanese/README.md](japanese/README.md) |
| **점프! 로봇** (게임) | `.../Project-begins/game/` | `game/` | [game/README.md](game/README.md) |

앱을 어떻게 쓰고 어떻게 고치는지는 **각 폴더의 설명서**에 있습니다.
이 문서는 세 앱에 **공통인 이야기**만 다룹니다 — 인터넷에 올리기, 홈 화면에 두기,
다른 기기에서 이어서 작업하기, 검사 돌리기.

### 폴더 구조

```
/                Dr. Y's Archive — 앱 목록 첫 화면 (index.html)
/psychiatry/     오늘의 정신의학 논문
/japanese/       오늘의 일본어 여행 회화
/game/           점프! 로봇
/tests/          자동 검사 (세 앱 것이 모두 여기 있습니다)
/tools/          아이콘 생성기, 스크린샷 도구
```

**왜 앱마다 폴더를 따로 두었나** — 앱을 설치하면 "여기서부터 아래는 내 영역"이라는
범위가 함께 저장됩니다. 논문 앱이 루트에 있던 동안에는 그 범위가 `japanese/` 폴더까지
삼켜버려서, 일본어 앱 주소를 열어도 **논문 앱 창에서 논문 앱 아이콘으로** 열렸습니다.
세 앱을 각자의 폴더로 내리고 루트에는 목록 페이지만 두어 범위가 겹치지 않게 했습니다.

> 그래서 루트 첫 화면에는 일부러 `manifest.json` 을 두지 않았습니다. 두면 다시 겹칩니다.
> 이 규칙은 `tests/html.test.mjs` 가 자동으로 지켜봅니다.

## Dr. Y's Archive — 첫 화면

```
https://logos113.github.io/Project-begins/
```

지금까지 만든 것을 한 화면에 모아 둔 서가입니다. 화면은 두 층입니다.

| 층 | 무엇 |
|---|---|
| **바로가기** (머리말 아래) | 아이콘만 늘어놓은 줄. 어디로 갈지 이미 알 때 바로 누릅니다 |
| **서가** (그 아래) | 앱마다 아이콘·이름·설명·만든 때가 한 칸씩 |

`index.html` **파일 하나**가 전부입니다. 디자인(CSS)도 그 안에 함께 들어 있습니다.
하는 일이 목록을 보여주는 것뿐이라 파일을 나눌 이유가 없었습니다.

### 앱을 새로 만들었을 때 — 서가에 거는 법

**두 군데**를 고쳐야 합니다. 각 자리에 방법을 적어두었습니다.

**(1) 바로가기 줄** — `<nav class="dock">` 안에 `<a>` 한 줄을 더합니다.

```html
<a href="recipe/" aria-label="앱 이름" title="앱 이름">
  <img src="recipe/icons/icon-192.png" alt="" width="192" height="192">
</a>
```

> `aria-label` 은 빠뜨리면 안 됩니다. 글자가 없는 링크는 화면 낭독기가
> "링크" 라고만 읽어서 어디로 가는지 알 수 없습니다.

**(2) 서가** — `<a class="item ...">` 한 덩어리를 복사해서 고칩니다.

1. `class` 의 둘째 이름을 새로 정하고, 위쪽 `<style>` 의 '왼쪽 테두리 색' 부분에
   같은 이름으로 네 줄을 더합니다
2. `href` 를 새 폴더 이름으로 (예: `"recipe/"`)
3. `src` 를 그 폴더의 아이콘 파일로
4. 제목·설명·꼬리표를 고칩니다
5. `만든 것 3` 의 숫자를 올립니다

> **빠뜨려도 검사가 잡아 줍니다.** `tests/html.test.mjs` 가 *폴더에 있는 앱* ·
> *바로가기에 있는 앱* · *서가에 걸린 앱* 셋의 수를 맞춰 보고, 화면에 적힌 숫자와
> 아이콘 파일 경로, `aria-label` 까지 확인합니다.
> 만들어 놓고 서가에 안 걸면 아무도 찾아갈 수 없는 앱이 되기 때문입니다.

**(3) 새 앱 쪽에도** 첫 화면으로 돌아가는 줄을 넣어주세요 (아래 참고).

### 앱에서 첫 화면으로 돌아가기

각 앱 위쪽에 `← Dr. Y's Archive` 줄이 있습니다 (게임은 시작 화면 아래).

```html
<p class="back-home"><a href="../">← Dr. Y's Archive</a></p>
```

앱끼리 서로 건너가는 링크는 두지 않기로 했는데, 이 줄은 **옆 앱이 아니라
한 칸 위인 목록 화면**으로 가는 것이라 그 규칙과 어긋나지 않습니다.

> **설치한 앱으로 열었을 때는 이 줄이 감춰집니다.** CSS 로 처리했습니다.
>
> ```css
> @media (display-mode: standalone), (display-mode: minimal-ui), (display-mode: fullscreen) {
>   .back-home { display: none; }
> }
> ```
>
> 설치한 앱은 **자기 폴더까지가 '내 영역'** 이라, 한 칸 위로 가면 앱 창이 아니라
> 브라우저가 따로 열립니다. 갑자기 다른 창으로 튀면 당황스럽고, 설치해서 쓰신다면
> **홈 화면이 이미 아카이브 역할**을 합니다. 그래서 브라우저에서 열었을 때만 보입니다.
>
> 이건 HTML 만 읽어서는 확인할 수 없어서, `tests/archive.test.mjs` 가 진짜 브라우저를
> 두 가지 모양(보통 창 / `--app` 으로 띄운 앱 모양)으로 열어 확인합니다.

**색을 고를 때 한 가지** — 앱 아이콘 색을 그대로 글자에 쓰면 흐릴 수 있습니다.
게임의 노란색(`#d9a441`)이 그랬습니다. 흰 바탕과의 대비가 2.25:1 로,
글자에 필요한 4.5:1 에 한참 못 미쳐서 같은 계열의 진한 색으로 바꿨습니다.

## 새 앱을 만들 때 — 차례대로

앱 하나를 더할 때 손대야 하는 곳이 여러 군데라, 순서대로 적어둡니다.
**빠뜨려도 대부분 검사가 잡아 줍니다.** 마지막에 검사를 한 번 돌려보세요.

### 1. 폴더 만들기

```
/새이름/
   index.html      화면 뼈대
   style.css       디자인
   app.js          동작
   manifest.json   앱으로 설치하기 위한 정보
   icons/          아이콘 그림들
   README.md       그 앱 설명서
```

앱은 **반드시 자기 폴더 안에** 두세요. 루트에 두면 설치 영역이 다른 폴더를
삼켜버립니다 (위 '폴더 구조' 참고).

### 2. `manifest.json` — 영역을 자기 폴더로 묶기

```json
{
  "name": "앱 이름",
  "short_name": "짧은 이름",
  "start_url": "./",
  "scope": "./",
  "display": "standalone",
  "icons": [ ... ]
}
```

> **`scope` 와 `start_url` 은 반드시 `"./"`** 입니다. `"/"` 로 적으면 저장소 전체가
> 그 앱의 영역이 되어, 다른 앱을 열어도 이 앱 창에서 열립니다.
> 이 규칙은 `tests/html.test.mjs` 가 앱마다 확인합니다.

### 3. 아이콘 만들기

`tools/make_icons_ja.py` 같은 기존 생성기를 복사해 색과 모양만 바꾸면 됩니다.
`icon-192.png` · `icon-512.png` · `icon-512-maskable.png` ·
`apple-touch-icon-180/167/152.png` · `favicon-32.png` 를 그 앱의 `icons/` 에 넣습니다.

### 4. 첫 화면에 걸기 (두 군데)

위 **[앱을 새로 만들었을 때 — 서가에 거는 법](#앱을-새로-만들었을-때--서가에-거는-법)** 참고.
바로가기 아이콘 한 줄 + 서가 한 칸 + `만든 것 N` 숫자.

### 5. 돌아가는 줄 넣기

위 **[앱에서 첫 화면으로 돌아가기](#앱에서-첫-화면으로-돌아가기)** 참고.
`.back-home` 한 줄과 그 CSS(설치 모드에서 감추는 부분까지) 복사.

### 6. 오프라인 준비 (서비스 워커)

기존 앱의 `sw.js` 를 복사해 두 군데만 고칩니다.

- `보관함_이름` 을 새 이름으로 (예: `"recipe-v1"`)
- `미리받을것` 목록을 그 앱의 파일들로

그리고 `app.js` 맨 아래의 **`오프라인_준비()` 블록**과 `style.css` 의
**`.sw-update` 부분**을 복사해 넣습니다. 자세한 설명은 아래
[오프라인과 새 버전 알림](#오프라인과-새-버전-알림) 참고.

> `sw.js` 는 **반드시 그 앱 폴더 안에** 두세요. 저장소 맨 위에 두면
> 한 워커가 세 앱을 전부 담당하게 되어, manifest 때 겪었던 영역 겹침 문제가
> 똑같이 생깁니다. `offline.test.mjs` 가 앱마다 담당 영역을 확인합니다.

### 7. 파일 번호 붙이기

`index.html` 에서 `style.css?v=1` 처럼 번호를 붙이고, 고칠 때마다 올립니다.
브라우저가 예전 파일을 계속 쓰지 않게 하는 표시입니다.

### 8. 검사 추가하고 돌리기

`tests/` 에 그 앱 검사를 하나 두면 좋습니다. 없더라도 **기존 검사는 꼭 돌려보세요.**
`html.test.mjs` 와 `archive.test.mjs` 는 앱 폴더를 **자동으로 찾아** 확인하므로,
새 앱도 그 순간부터 검사 대상이 됩니다.

```bash
for f in tests/*.test.mjs; do node "$f"; done
```

### 9. 설명서 쓰기

`새이름/README.md` 를 만들고, 저장소 첫 문서(이 파일)의 **'무엇이 들어 있나'** 표에
한 줄 더합니다. `html.test.mjs` 가 앱마다 설명서가 있는지, 첫 문서가 그것을
가리키는지 확인합니다.

## 오프라인과 새 버전 알림

세 앱 모두 **한 번 열어본 뒤로는 인터넷 없이도 열립니다.**
비행기 모드, 지하철, 해외 로밍이 안 될 때도 그대로 씁니다.

`앱폴더/sw.js` (서비스 워커)가 하는 일입니다. 페이지와 인터넷 사이에 서 있는
중계원이라고 보시면 됩니다. 앱을 이루는 파일을 기기에 보관해 두었다가,
요청이 오면 인터넷 대신 그것을 내어 줍니다.

| 앱 | 인터넷 없을 때 |
|---|---|
| 일본어 회화 | **전부 됩니다** — 표현이 파일 안에 있어서 완전한 오프라인 앱입니다 |
| 점프! 로봇 | **전부 됩니다** |
| 정신의학 논문 | 화면은 뜨고, **저장한 논문**은 볼 수 있습니다. 새 논문은 인터넷이 필요합니다 |

### 두 가지 방식을 섞어 씁니다

```
페이지(HTML)         → 인터넷 먼저, 안 되면 보관해 둔 것
나머지(css·js·그림)  → 보관해 둔 것 먼저, 뒤에서 몰래 새것 받아두기
```

HTML 까지 보관함 먼저로 하면 **고쳐서 올려도 예전 화면이 계속 나옵니다.**
"고쳤는데 왜 그대로지?" 하는 문제가 훨씬 지독해집니다. 그래서 화면만은
늘 인터넷을 먼저 봅니다.

### 새 버전이 올라오면

화면 아래에 **`새 버전이 있습니다 [지금 받기]`** 줄이 뜹니다. 누르면 끝입니다.
**강제 새로고침을 하실 필요가 없습니다.**

곧바로 갈아끼우지 않고 물어보는 이유는, 보고 있는 도중에 파일이 바뀌면
화면이 어긋날 수 있기 때문입니다. 나중에 받으시려면 ✕ 로 닫으면 됩니다.

> **첫 화면(Dr. Y's Archive)에는 서비스 워커를 두지 않았습니다.**
> 저장소 맨 위에 두면 그 워커가 세 앱을 전부 담당하게 되어, manifest 때와
> 똑같이 영역이 겹칩니다. 첫 화면은 목록일 뿐이라 오프라인이 될 필요도 없습니다.

### 만들면서 겪은 것 두 가지

서비스 워커는 잘못 만들면 골치 아픕니다. 실제로 두 번 어긋났고
둘 다 `tests/offline.test.mjs` 가 잡았습니다.

1. **앱을 열 때마다 화면이 한 번 깜빡였습니다.** 처음 설치될 때도 '워커가
   바뀌었다' 는 신호가 오는데, 그걸 갱신으로 착각해 새로고침했습니다.
2. **'지금 받기' 를 눌러도 화면이 새로 안 그려졌습니다.** 1번을 막으려고 둔
   조건이 너무 뭉툭해서, 직접 누른 교대까지 막아버렸습니다.

## 1단계 — 인터넷에 올리기 (아이패드·아이폰에서는 필수)

아이패드·아이폰의 사파리는 **기기에 저장된 파일이 외부 인터넷으로 요청 보내는 것을
보안상 막습니다.** 그래서 파일을 탭해서 여는 방법은 통하지 않습니다.
대신 인터넷에 올리면 됩니다. 무료입니다.

### GitHub Pages로 올리기 (아이패드 사파리만으로 가능, 약 3분)

1. 사파리에서 저장소를 엽니다 → `https://github.com/logos113/Project-begins`
2. 위쪽 탭 중 **Settings** (톱니바퀴)를 탭합니다
   *탭이 안 보이면 주소창 왼쪽 `ᐕ` → **데스크탑 웹사이트 요청**을 선택하세요*
3. 왼쪽 메뉴를 내려서 **Pages** 를 탭합니다
4. **Source** 를 `Deploy from a branch` 로 둡니다
5. **Branch** 에서 `main` 을 고르고, 옆은 `/ (root)` 로 둔 뒤 **Save**
6. 1~2분 기다린 뒤 `https://logos113.github.io/Project-begins/` 를 엽니다

> 처음엔 404가 뜰 수 있습니다. **1~2분 뒤 새로고침**하면 나옵니다.

**한 번만 해두면 됩니다.** 이후로는 `main` 에 올라간 내용이 자동으로 배포됩니다.
세 앱이 한 브랜치 안에 폴더만 나뉘어 함께 들어 있으므로, 브랜치를 바꿔가며 쓸 필요가 없습니다.

## 2단계 — 홈 화면·바탕화면에 앱처럼 두기

세 앱은 서로 다른 주소라 **각각 따로** 추가해야 합니다.
추가·설치는 **그때 열려 있던 주소를 기억**하므로, 원하는 앱을 먼저 연 다음에 하세요.

### 아이패드·아이폰 (사파리)

1. 사파리에서 그 앱의 주소를 엽니다
2. 화면이 **다 뜬 뒤에** 공유 버튼(⬆️) → **홈 화면에 추가** → **추가**

홈 화면에 아이콘이 생기고, 탭하면 주소창 없이 전체 화면으로 열립니다.

> 아이패드는 홈 화면에 추가하는 **그 순간의 아이콘을 저장해두고 다시 확인하지 않습니다.**
> 페이지가 다 뜨기 전에 추가하면 아이콘이 글자로 굳어버립니다.
> 아래 "문제가 생겼을 때"를 참고해 지우고 다시 추가하시면 됩니다.

### 데스크탑 (크롬·엣지)

## 아이패드로 작업할 때 — 코드 고치는 방법

아이패드에는 메모장이나 터미널이 없지만, **브라우저만으로 코드를 고칠 수 있습니다.**

### 방법 A — GitHub 웹 편집기 (간단한 수정용)

1. 사파리에서 저장소를 열고 고칠 파일(`app.js` 등)을 탭
2. 오른쪽 위 **연필 아이콘** ✏️ 을 탭
3. 내용을 고친 뒤 아래로 내려 **Commit changes** 를 탭
4. 1~2분 뒤 배포된 주소를 새로고침하면 반영됩니다

### 방법 B — github.dev (여러 파일을 함께 볼 때)

주소창에서 `github.com` 을 **`github.dev`** 로 바꾸면 됩니다.

```
https://github.dev/logos113/Project-begins
```

VS Code라는 전문 편집기의 웹 버전이 열립니다. 왼쪽에 파일 목록이 나오고,
고친 뒤 왼쪽 갈래 아이콘에서 저장(Commit)하면 됩니다. **설치할 것은 없습니다.**

> 아이패드 화면 키보드로는 `{ }` `[ ]` 같은 기호를 치기가 번거롭습니다.
> **처음에는 저에게 "이렇게 바꿔줘" 라고 말씀하시는 편이 훨씬 빠릅니다.**
> 코드가 눈에 익은 다음에 직접 고쳐보셔도 늦지 않습니다.

### 아이패드에서 안 되는 것

- **터미널 명령** (`npm`, `node`, `python3`) — 5단계의 테스트 실행이 여기 해당합니다.
  필요할 때 저에게 말씀해 주시면 제가 대신 돌려서 결과를 알려드리겠습니다.
- 그 외에는 데스크탑과 차이가 없습니다.

## 다른 기기에서 이어서 작업하기 (아이패드 ↔ 데스크탑)

**코드는 아이패드가 아니라 GitHub에 저장되어 있습니다.** 그래서 어느 기기에서든
이어서 작업할 수 있습니다. 기기를 바꿔도 처음부터 다시 만들 필요가 전혀 없습니다.

```
              ┌──────────────────┐
              │     GitHub       │  ← 진짜 원본
              └────────┬─────────┘
         받아오기 ↓        ↑ 올리기
        ┌──────────────┴──────────────┐
     아이패드                      데스크탑
```

### 방법 1 — 아무것도 설치하지 않기 (가장 쉬움)

데스크탑에서도 브라우저로 그냥 하면 됩니다. 아이패드와 완전히 똑같습니다.

```
https://github.dev/logos113/Project-begins
```

설치할 것도, 받아올 것도 없습니다. **어느 기기에서든 항상 최신 상태**입니다.
기기를 자주 바꾸신다면 이 방법이 제일 속 편합니다.

### 방법 2 — 데스크탑에 제대로 갖추기 (권장)

> **윈도우 PC를 쓰신다면 [SETUP-WINDOWS.md](SETUP-WINDOWS.md) 에 설치부터 첫 실습까지
> 단계별로 자세히 적어두었습니다.** 아래는 요약입니다.

코드가 늘어나면 내 컴퓨터에 두고 작업하는 편이 훨씬 편합니다.
**명령어를 몰라도 됩니다.** 클릭으로 하는 프로그램이 있습니다.

**설치할 것 2개 (둘 다 무료)**

| 프로그램 | 역할 | 주소 |
|---|---|---|
| **GitHub Desktop** | GitHub에서 받아오고 올리기 | desktop.github.com |
| **VS Code** | 코드 편집기 | code.visualstudio.com |

**처음 한 번만 하는 설정**

1. GitHub Desktop 실행 → GitHub 계정으로 로그인
2. `File` → `Clone repository` → 목록에서 **Project-begins** 선택 → `Clone`
   *(Clone = 내 컴퓨터로 복사해오기)*
3. 저장할 폴더를 정하면 끝입니다. 코드가 내 컴퓨터에 생깁니다.

**작업할 때마다 하는 3단계**

```
① 시작 전   GitHub Desktop 에서  Fetch origin  →  Pull  (최신 내용 받아오기)
② 작업      VS Code 로 파일을 고치고 저장
③ 끝나면    GitHub Desktop 에 바뀐 내용이 뜸
            → 아래에 무엇을 고쳤는지 한 줄 적고  Commit  →  Push
```

### ⚠️ 가장 많이 겪는 문제 — 반드시 읽어주세요

**작업을 시작하기 전에 항상 먼저 받아오세요(Pull).**

이런 상황을 조심해야 합니다.

```
월요일  아이패드에서 색깔을 바꾸고 Commit          → GitHub에 반영됨
화요일  데스크탑에서 Pull 을 안 하고 그냥 작업       → 내 컴퓨터는 아직 월요일 이전 상태
        Push 하려고 하면 "충돌(conflict)" 이라며 거부당함
```

**규칙은 하나뿐입니다: 작업 시작 = Pull, 작업 끝 = Push.**
이것만 지키면 거의 문제가 생기지 않습니다.

혹시 충돌이 나더라도 **코드가 사라지지는 않습니다.** GitHub에는 모든 기록이 남아 있어서
언제든 되돌릴 수 있습니다. 막히시면 저에게 말씀해 주세요.

### 저(Claude)와의 대화는 어떻게 되나요?

- **코드**는 GitHub에 있으므로 100% 안전합니다.
- **대화 기록**은 같은 계정으로 `claude.ai/code` 에 접속하면 세션 목록에서 찾을 수 있습니다.
  데스크탑 앱이나 브라우저 어느 쪽이든 됩니다.
- 설령 예전 대화를 못 찾더라도 괜찮습니다. **이 README가 인수인계 문서 역할**을 합니다.
  새 대화를 열고 이 저장소를 보여주면서 "이어서 작업하고 싶다"고 말씀하시면 됩니다.
  그래서 무엇을 왜 만들었는지 여기에 자세히 적어둔 것입니다.

## 앞으로 작업할 때

- 인터넷에 올라가는 것은 늘 **`main`** 입니다. 주소와 홈 화면 아이콘은 그대로 유지됩니다.
- 파일을 고친 뒤에는 `index.html` 의 `?v=` 숫자를 올려주세요.
  브라우저가 예전 파일을 계속 쓰지 않도록 알려주는 표시이고,
  화면 맨 아래 "화면 버전"에 그 숫자가 그대로 보입니다.

### 브랜치는 어떻게 쓰고 있나

지금은 **`main` 하나로 충분합니다.** 혼자 만들고 있고, 고친 것을 바로 확인하는
방식이라 여러 갈래로 나눌 이유가 없습니다. 기록도 한 줄로 곧게 이어져 있습니다.

`claude/...` 로 시작하는 브랜치가 하나 더 보일 수 있습니다. Claude 와 작업할 때
자동으로 만들어지는 작업용 브랜치인데, 지금은 `main` 과 **내용이 완전히 같습니다.**
헷갈리시면 GitHub 웹에서 지우셔도 됩니다 — `main` 에 모든 내용이 들어 있습니다.

> 나중에 큰 기능을 만들 때, 중간 상태를 인터넷에 올리고 싶지 않다면 그때
> 작업용 브랜치를 쓰시면 됩니다. 다 만든 뒤 `main` 에 합치면 그때 배포됩니다.

## 문제가 생겼을 때

### 고쳤는데 화면이 그대로일 때 (가장 흔한 문제)

브라우저가 예전 파일을 계속 쓰고 있는 것입니다. **먼저 화면 아래쪽 "화면 버전"을 확인하세요.**

```
화면 버전 v7     ← 이 숫자가 최신이면 반영된 것입니다
```

숫자가 낮으면 예전 파일을 보고 계신 것입니다. 이렇게 해결합니다.

1. **10분쯤 기다렸다 새로고침** — 대개 이것으로 해결됩니다
   (GitHub Pages 는 페이지를 10분 정도 브라우저에 저장해두도록 지시합니다)
2. 급하면 **주소 뒤에 `?v=아무숫자`** 를 붙여 여세요 → `.../Project-begins/psychiatry/?v=99`
3. 그래도 안 되면 `설정` → `Safari` → `방문 기록 및 웹사이트 데이터 지우기`

**홈 화면 아이콘으로 열 때만 옛날 화면이 나온다면**, 아이콘에 예전 주소가
저장돼 있기 때문입니다. 아이콘을 삭제하고, 주소 뒤에 아무것도 붙지 않은
그 앱의 주소로 접속한 뒤 다시 추가하세요.

### 홈 화면 아이콘이 그림이 아니라 글자로 나올 때

**먼저 다시 추가해 보세요.** 아이패드는 홈 화면에 추가하는 그 순간의 아이콘을
저장해두고 다시 확인하지 않습니다.

1. 홈 화면의 기존 아이콘을 **길게 눌러 삭제**합니다
2. 사파리에서 그 앱의 주소를 엽니다 (위 표 참고)
3. **페이지가 완전히 다 뜰 때까지 기다립니다** (내용이 다 보일 때까지)
4. 그 상태에서 공유 버튼(⬆️) → **홈 화면에 추가**

그래도 안 되면 사파리 캐시를 지우고 다시 시도하세요.
`설정 앱` → `Safari` → `방문 기록 및 웹사이트 데이터 지우기`

**그것도 안 된다면 페이지 구조가 깨졌을 수 있습니다.**
iOS는 홈 화면 아이콘을 `<head>` 안에서만 찾기 때문에, 어떤 이유로든
아이콘 설정이 `<body>` 로 밀려나면 아이콘을 아예 못 찾습니다.
아래 검사를 돌리면 바로 알 수 있습니다.

```bash
node tests/html.test.mjs
```

아이패드에서는 실행할 수 없으니 Claude에게 확인을 부탁하세요.
참고로 화면 맨 위에 `====` 같은 이상한 글자가 보인다면 구조가 깨졌다는 신호입니다.

## 그 밖에

### 일반 도메인 연결 (`.com`, `.kr`)

GitHub Pages 는 커스텀 도메인을 정식 지원합니다. **호스팅은 계속 무료**이고
도메인 구입비만 듭니다 (.com 연 1.5~2만원, .kr 연 2~3만원).

1. 도메인 구입 (가비아·후이즈 / Cloudflare·Namecheap)
2. 구입처 DNS 설정에서 GitHub 주소를 가리키게 지정
3. 저장소에 `CNAME` 파일 추가
4. Settings → Pages → Custom domain 입력 → **Enforce HTTPS** 체크

HTTPS 인증서는 GitHub 가 무료로 발급하고, 기존 주소도 계속 함께 작동합니다.
DNS 에 넣을 IP 는 바뀔 수 있으니 설정할 때 GitHub 공식 문서에서 확인하세요.

> 개인 용도라면 굳이 없어도 됩니다. 남에게 보여주거나 여러 사람이 쓰게 될 때 의미가 있습니다.
